# Handoff：评测集原料提取（agent-retrieval → 外部工程）

> 交接日期：2026-11-06。本文档自包含：提取方无需阅读 agent-retrieval 仓库其他文档即可执行；引用出处以括号标注，供需要深挖时回查。
> 提取目标：为 agent-retrieval 检索库的两个自建评测场景提供**真实数据原料**。提取完成后的构建流程在本仓进行（见「交回与接回」节）。

## 一、背景：为什么需要这些数据

`agent-retrieval` 是一个确定性 BM25 + 向量双路融合的检索库（资源池里检索工具/技能/知识条目）。公开基准（ToolRet/SkillRet）已验证了质量杠杆，但**自有域**的表现需要自建评测集验证。两个消费场景：

1. **zh-plot-v1**（issue #4 冻结方案）：智能标绘域的 query 级检索基准——需要**几百条真实工具声明面**做原料（对每工具用 LLM 生成 query、逆频采样挑 100 条、双人标注 κ≥0.7 冻结）。
2. **e2e 端到端评测**（`experiments/agent-e2e-evaluation-design.md`）：Agent 执行任务的安全完成率基准——需要**50-100 条脱敏真实用户任务**做用例原料（校准集 ~20 + 留出集 ~80）。

两项共用第二标注者人力，数据原料是它们的前置——**这就是本次提取的目的**。

## 二、交付物 A：工具/资源声明面池（zh-plot-v1 原料）

### 要什么

从你的工程提取**全部可检索资源**的声明面数据（面向用户的自我描述，不是实现代码）：

| 字段 | 必需性 | 说明 |
|---|---|---|
| `id` | 必需 | 全局唯一标识（本仓用作主键与快照键，提取时保持稳定——同一资源重新导出 id 不得变） |
| `name` | 必需 | 资源名（LLM 交叉审查与 query 防泄漏规则以此为 gold 名） |
| `description` | 必需 | **声明面正文**：该资源能做什么、适用边界。这是质量关键——下游「LLM 交叉审查 gold 能执行吗」完全依赖它。够一个陌生模型判断「这个请求该不该找它」为合格 |
| 参数表 / `tags` / 分类 | 尽量提供 | 冻结方案的投影原则是「全部声明字段进语料面」——字段清单随你的工具集落地，有多少给多少 |

### 量与分布

- **目标几百条**（zh-plot-v1 是「全量生成 → 逆频采样挑 100」，原料越全，长尾覆盖越好）。
- **长尾优先**：热门工具人人知道，逆频采样的意义在长尾——提取时不要只挑核心工具，冷门资源（低频、新上架、领域专用）是价值所在。
- 中文工程直接提取即可（zh-plot-v1 是中文场景）；英文工程也收（双语声明面在本仓有成熟处理），但请在交付说明里标注语言构成。

### 脱敏红线

- 替换：内部系统名/代号、密钥与凭据、内网 URL/主机名、真实人名与邮箱、客户敏感数据。
- 保留：语义完整性——**脱敏不得让声明面变得无法判断资源能力**（否则下游「gold 能执行」审查失效，该条等于白提取）。
- 脱敏映射表单独保存（不进交付物），便于提取方自查。

### 形状

JSON 数组，每条一个对象（字段名照上表；多余字段保留不删——下游按需取用）：

```json
[
  {"id": "chart-render", "name": "Chart Renderer", "description": "Render bar and line charts from supplied numeric data.", "tags": ["visualization"]}
]
```

## 三、交付物 B：真实用户请求样本（e2e 用例原料）

### 要什么

脱敏的**真实用户请求**（用户对 Agent/系统说过的原话，非人工编写）：

- **量**：50-100 条（e2e 留出集 ~80 + 校准集 ~20 的原料池）。
- **覆盖切片**（设计稿 §3.1 要求的用例形态，原料阶段按此分层收集）：简单请求 / 多步任务 / 精确资源提及 / 改写（同一意图不同说法）/ 无匹配（请求了不存在的能力）/ 信息不足（歧义）/ 无权限场景 / 工具故障后的请求。稀有形态（无匹配、歧义、故障）可以超采样。
- **每条附最小上下文**：涉及哪些资源（若可知）、当时可用的权限范围（若可知）。缺省可空。

### 形状

JSONL，每行一条：

```json
{"request": "Find a free hour with Mei next Tuesday and schedule a meeting", "involved_resources": ["calendar-create"], "note": ""}
```

### 脱敏红线

同交付物 A；另注意请求文本里的真实人名→字母代号（Mei/Alex 这类中性名即可，e2e 用例本来就用代号）。

## 四、提取操作注意事项（坑位清单）

1. **id 稳定性**：`id` 是后续所有流程（快照键、gold 引用、防泄漏比对）的主键——两次导出同一资源必须同 id。用工程内的稳定主键，不要用序号。
2. **声明面 ≠ 实现摘要**：description 取「面向用户/调用方的描述文档」，不是代码注释或实现逻辑——下游测的是「检索面能否把对的资源排上来」，实现细节是噪声。
3. **多版本/重复资源**：同能力多版本（v1/v2）合并为一条或分别保留都行，但要在交付说明里写明规则；重复条目（同 id 出现两次）会被本仓加载器直接拒收。
4. **空描述/占位描述剔除**：description 为空或「TODO」「暂无」的条目没有声明面价值，剔除。
5. **不要预先做 query 生成**：query 生成是本仓流程的第 1 阶段（glm-5.3 正式版、每工具 3 条、防泄漏双硬规则——见 issue #4 resolution），提取方**只供原料**，生成的 query 不合格率会很高且走样。
6. **不要预先格式化成 e2e 用例**：交付物 B 只是请求原话 + 上下文——`required_state`/`forbidden_effects`/权限模型的用例化是本仓 e2e 阶段 0 契约的工作，需要工具语义知识，放提取方做会失真。

- **交回**：两个交付物（`resources.json` + `requests.jsonl` + 一份交付说明：语言构成/提取范围/脱敏规则概要/已知缺口）打包交给主会话，或放到本仓 `experiments/data/`（目录不存在则创建，`.gitignore` 若有影响会由主会话处理）。
- **接回后**（本仓流程，供了解时序）：
